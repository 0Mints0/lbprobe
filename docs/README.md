## 建议的阅读顺序

1. 先读 `README.md` 的「它怎么定义"等待"」一节 —— 后面的一切都建立在这个定义上；
2. 再翻一份 `samples/01-imbalanced-load-report.md`，看口径在真实输出里长什么样；
3. 要动手就跳到 `usage.md`；
4. `case-study.md` 里有一节（第 4 节）专门解释**为什么"等待更少"可能是坏事**，值得一读。

## 一个容易误读的地方

报告里的「相互等待时长」是**绝对量**，它不能直接用来给两个不同的程序版本排名。

跨进程同步点多的那个版本，即使每次同步等得很少，累计量也会更大。
本工具能帮你做的是**在同一套同步结构下**回答：等待集中在哪个调用点、该归因给谁、占墙钟多少比例。
跨版本比较请先看 `case-study.md` 第 4 节和 `method.md` 的判定章节。
