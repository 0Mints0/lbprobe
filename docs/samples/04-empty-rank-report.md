## 0. 结论

### 存在相互等待

同步点等待合计 10472.1 rank·ms，占 墙钟×进程数 的 69.96%；平均 5.60 个 rank 同时在等待（占 70.0%）。其中 75% 属于到齐前等待（我算完了在等其它进程），合计 **7834.0 rank·ms**（≈ 7.834 核·秒）。 等待分散在多个进程之间（最集中的 rank 5 也只占 16%），属于进程之间进度不一致造成的相互等待。

| 关键量 | 值 |
|---|---|
| **相互等待时长（到齐前等待合计）** | **7834.01 rank·ms**（7.8340 核·秒） |
| 同步点等待合计（相互等待 + 原语开销） | 10472.11 rank·ms（10.4721 核·秒） |
| 其中：到齐前等待（相互等待） | 7834.01 rank·ms（占 75%） |
| 其中：到齐后通信耗时（原语开销） | 2638.10 rank·ms（占 25%） |
| 平均同时在等待的 rank 数 | 5.597 / 8（69.96%） |
| 等待占 墙钟×进程数 的比例 | 69.963% |
| 最大到达离散度 | 200.40 ms |
| 最集中的最后到达者 | rank 5（占同步点的 15.83%） |

> 判定阈值（可在命令行调整）：平均同时在等待的 rank 占比 < 5% 视为无实际影响；到齐前等待占全部等待 ≥ 50% 且最后到达者分散在多个进程之间，判定为相互等待。
